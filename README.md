**An embeddable TypeScript agent runtime.** Model→tool loop, pipelines, checkpointing,
interrupts, compression, delegation, and a vendor-neutral observability seam —
with zero production dependencies.

## Why this exists

Agent frameworks usually decide too much on your behalf: they assume an HTTP server, a
database, a session model, and a UI. This one assumes none of them.

`red-bean-qing-tuan` is the execution layer and nothing else. It runs the model→tool loop,
persists checkpoints through a store *you* provide, and emits neutral events. HTTP, SSE,
databases, caches, authentication, and product sessions stay in the host — where they can be
shaped to fit the product instead of the framework.

It has **zero production dependencies** and ships as ESM JavaScript with type declarations and
source maps. Adopting it does not add a dependency tree to your service.

## Quick start

```ts
import { AgentRuntime, MemoryCheckpointStore } from 'red-bean-qing-tuan'
import { OpenAiAdapter } from 'red-bean-qing-tuan/llm'

const runtime = new AgentRuntime({
  model: new OpenAiAdapter({
    apiKey: process.env['OPENAI_API_KEY'] ?? '',
    modelName: 'gpt-4',
  }),
  checkpointStore: new MemoryCheckpointStore(),
  systemPrompt: 'You are an assistant.',
})

const result = await runtime.run(
  { threadId: 'session-1', userId: 'user-1', input: 'Hello' },
  AbortSignal.timeout(60_000)
)

if (result.status === 'suspended' && result.interrupt !== undefined) {
  await runtime.resume(
    {
      threadId: 'session-1',
      userId: 'user-1',
      requestId: 'resume-1',
      interruptId: result.interrupt.toolCallId,
      response: '{"approved":true}',
    },
    AbortSignal.timeout(60_000)
  )
}

await runtime.close(AbortSignal.timeout(10_000))
```

`RuntimeResult.status` distinguishes `completed`, `suspended`, `exhausted`, `cancelled`, and
`failed`. Failures throw `RuntimeExecutionError`, whose `result` carries partial output and a
diagnosable checkpoint.

`MemoryCheckpointStore` is a development and contract-reference implementation — it is **not**
a cross-instance production store.

## What the runtime owns, and what it does not

This boundary is the whole point of the library, so it is worth stating precisely.

**The runtime owns:**

- The ReAct state machine, model streaming, tool scheduling, cancellation, and timeouts.
- The interrupt execution barrier and persistent checkpoints with idempotent resume.
- Neutral run events and a structured `Result`.
- Safe-by-default builtin tools, plus explicitly named high-privilege constructors.

**The host owns:**

- HTTP / SSE / WebSocket protocols, UI sections and cards, and localization.
- User identity, session lists and titles, authentication, and approvals.
- Cache and database keys, scheduled-task metadata, sub-execution records.
- Which network destinations are allowed, which filesystem roots are reachable, and how
  secrets are supplied.

Concretely: the runtime does **not** provide leases, TTLs, heartbeats, claim-timeout takeover,
or exactly-once external side effects. Fencing protects checkpoint commits only. Those are
host policies, and pretending otherwise would be a lie of omission.

## Checkpoint and concurrency

- A normal run loads revision `R` and saves the result with a CAS to `R+1`.
- `resume` first consumes the interrupt atomically (`R→R+1`), then saves the terminal state
  under a claim owner (`R+1→R+2`).
- Replaying a completed `requestId` returns the stored receipt without calling the model
  again; conflicting requests fail closed.
- Non-zero fencing tokens are generated by the host's lease system. The runtime and store
  reject stale fences.

Custom stores should run the framework-agnostic contract suite:

```ts
import {
  runCheckpointStoreContract,
  runCheckpointStoreFencingUnsupportedContract,
} from 'red-bean-qing-tuan/testing'

await runCheckpointStoreContract(() => new CustomCheckpointStore(), {
  supportsFencing: true,
  dispose: async (store) => store.close(),
})
```

Implementations that do not support fencing should also run
`runCheckpointStoreFencingUnsupportedContract`, which asserts that non-zero tokens fail closed.

## Interrupts

Any tool may return a structured `InterruptSignal` to suspend the run. An interrupt is an
**execution barrier**: no other tool in the same batch runs before the answer arrives. Callers
using the high-level API continue with `runtime.resume`; hosts driving the lower-level pipeline
append a tool message matching `interrupt.toolCallId` and continue.

Product cards, CLI prompts, and localized copy are the host's responsibility — the runtime
never formats user-facing text.

## Builtin tool safety

- `lookupBuiltinTool(id)` returns a fresh instance for `sys_get_time`, `sys_http_request`, and
  `sys_fetch_url` only. It registers no global state.
- HTTP and fetch refuse private, loopback, link-local, multicast, CGNAT, and unspecified
  addresses by default, and re-check on connection and on every redirect.
- `createRootedReadTool(root)` blocks path and symlink escapes. `UnrestrictedReadTool` is only
  appropriate for hosts that already run inside a process-level filesystem sandbox.
- Tools that can touch files, networks, or delegate work must be explicitly injected and
  authorized by the host.

## Plugins and observability

`plugins` are registered at `AgentRuntime` construction and closed thereafter. A plugin may
wrap run/resume, model, and tool calls, and may register shutdown functions. Earlier-registered
middleware sits further out, and no plugin can short-circuit `ToolPolicy`.

`red-bean-qing-tuan/observability` provides a neutral `Tracer` and `RuntimeTracePlugin`. The
default span hierarchy is:

```text
agent.run / agent.resume
├── llm.stream
└── tool.execute
    └── agent.delegate
```

`Span.within(operation)` propagates the parent span explicitly. The runtime ships no exporter
and no vendor SDK, and never records prompts, tool arguments, or model output. Choose
structured logging, OpenTelemetry, or your own adapter.

## Runtime 负责什么，不负责什么

这条边界是这个库存在的全部理由，所以值得写清楚。

**Runtime 负责：**

- ReAct 状态机、模型流、工具调度、取消与超时。
- interrupt 执行屏障，以及带幂等 resume 的持久化 checkpoint。
- 中性运行事件和结构化 `Result`。
- 默认安全的内置工具，以及必须显式点名才能用的高权限构造。

**宿主负责：**

- HTTP / SSE / WebSocket 协议、UI section 与卡片、本地化。
- 用户身份、会话列表与标题、鉴权与审批。
- 缓存与数据库 key、定时任务元数据、子执行记录。
- 允许哪些网络目标、可达哪些文件系统根、密钥如何注入。

具体一点：Runtime **不**提供 lease、TTL、heartbeat、claim 超时接管或 exactly-once 外部副作用。
fencing 只保护 checkpoint 提交。这些都是宿主策略 —— 假装 Runtime 能兜住它们，就是隐瞒。

## Checkpoint 与并发边界

- 普通 run 从 revision `R` 加载，成功以 CAS 保存为 `R+1`。
- `resume` 先原子消费 interrupt（`R→R+1`），再以 claim owner 保存终态（`R+1→R+2`）。
- 相同 `requestId` 会重放已完成的回执，不重复调用模型；请求冲突时直接 fail-closed。
- 非零 fencing token 由宿主的 lease 系统生成；Runtime 和 Store 拒绝 stale fence。

自定义 Store 应运行框架无关的契约套件：

```ts
import {
  runCheckpointStoreContract,
  runCheckpointStoreFencingUnsupportedContract,
} from 'red-bean-qing-tuan/testing'

await runCheckpointStoreContract(() => new CustomCheckpointStore(), {
  supportsFencing: true,
  dispose: async (store) => store.close(),
})
```

不支持 fencing 的实现还应运行 `runCheckpointStoreFencingUnsupportedContract`，
保证非零 token 明确 fail-closed。

## Interrupt

任何 Tool 都能返回一个结构化的 `InterruptSignal`，以此请求挂起。interrupt 是**执行屏障**：同批其他工具不会在确认前
执行。高层调用方使用 `runtime.resume`；低层 Pipeline 宿主把匹配 `interrupt.toolCallId` 的 tool message
追加后继续运行。

产品卡片、CLI 提示和本地化文案均由宿主负责 —— Runtime 从不拼装面向用户的文案。

## 内置工具安全

- `lookupBuiltinTool(id)` 只为 `sys_get_time`、`sys_http_request`、`sys_fetch_url` 返回新实例，
  不注册任何全局状态。
- HTTP/fetch 默认拒绝私网、回环、链路本地、组播、CGNAT 和未指定地址，并在建连与每次重定向前复核。
- `createRootedReadTool(root)` 阻止路径和 symlink 逃逸。`UnrestrictedReadTool` 只适用于已有进程级
  文件系统沙箱的宿主。
- 文件、网络和委派能力必须由宿主显式注入与授权。

## 插件与观测

`plugins` 只在 `AgentRuntime` 构造期注册，随后封闭。插件可以包装 run/resume、模型和工具调用，
也可以登记关闭函数。先注册的 middleware 位于外层，且任何插件都不能短路 `ToolPolicy`。

`red-bean-qing-tuan/observability` 提供中性 `Tracer` 与 `RuntimeTracePlugin`，默认 span 层级为：

```text
agent.run / agent.resume
├── llm.stream
└── tool.execute
    └── agent.delegate
```

`Span.within(operation)` 显式传播父 span。Runtime 不引入 exporter 或厂商 SDK，也从不记录 prompt、
工具参数或模型输出。请自行选择结构化日志、OpenTelemetry 或其他适配器。
