# 决策：注释治理与决策记录机制（含字面量成员引用护栏）

状态：已接受
日期：2026-09-10

背景：宿主仓（red-bean-nian-gao）按统一治理完成注释规范升级后，本仓作为 SDK 同步
同一套"为什么"治理，避免两仓注释标准分叉。同时把"字面量联合必须成员引用"作为硬性护栏。

选项：
- 仅复制规则条文（选定）：AGENTS.md 注释规范升级 + standards 增加字面量护栏 +
  docs/decisions/ 目录建立。
- 顺带全仓代码改造：实测本仓 0 处 `=== '` / `case '` 字面量比较（`RUN_KINDS`、
  `CHECKPOINT_STATUSES` 等 const 模式已在用），无需改造，只需护栏防回退。

决策：规则同步 + 决策记录机制落地。内容：
1. 注释规范分层（公开用例方法职责注释为义务；方法内"意图/不变量/分支依据"最高价值，
   翻译式允许；`// ── 阶段名 ──` 分段推荐；失真注释为唯一红线，须与代码同 diff 更新）。
2. 跨任务决策记入 `docs/decisions/`（ADR 式，只追加不修改），代码注释只承载局部"为什么"。
3. 字面量联合比较与 case 标签必须引用 const 成员（`CODE.X`），无 const 源先建映射。

理由：与宿主治理同构，降低双仓维护认知成本；SDK 现网代码已天然合规，规则成本≈0。

后果：
- 两仓 REVIEW 口径一致：公开方法职责、失真红线、决策记录。
- 新增决策从此入 `docs/decisions/`；提交 SDK 后宿主 `runtime.lock` 需同步更新。
